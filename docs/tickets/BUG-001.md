## 🔍 QA バグ報告

**対象バージョン**: v0.1.0（`9357e6f`）

**再現手順**
1. DB を起動し、`flask --app app run` でアプリを起動する
2. `curl -i -X POST http://127.0.0.1:5000/health` を実行する
3. `PUT` / `DELETE` でも同様に実行する

**期待結果**
- ステータス 405、JSON ボディ（D-017 形式）
- レスポンスヘッダーに `Allow: GET, HEAD, OPTIONS`（順不同）が含まれること
  - 根拠: RFC 9110 §15.5.6「405 応答ではサーバーは Allow ヘッダーを生成しなければならない (MUST)」

**実際の結果**
- ステータス 405、JSON ボディは正しい
- **`Allow` ヘッダーが存在しない**

**補足（デグレの根拠）**
- PR #1（SETUP-001 時点）の PR 本文の curl 結果には `Allow: GET, OPTIONS, HEAD` が出ていた
- PR #2（SETUP-003）の PR 本文の curl 結果から `Allow` が消えている
- → SETUP-003 の JSON エラーハンドラ導入時にヘッダーが失われたと推測

**QA が確認した他のケース（問題なし）**
| リクエスト | 結果 |
|---|---|
| GET /health（DB 正常） | 200 JSON |
| HEAD /health | 200 |
| OPTIONS /health | 200、`Allow` あり |
| GET /health/（末尾スラッシュ）, /HEALTH, /static/x.js | 404 JSON |
| DB 停止時 GET /health | 503 JSON、数秒以内 |

---

## 🧑‍💼 TL トリアージ
- 原因（推定・TL 確認済み）: `handle_http_exception` が `jsonify(...)` で**新しいレスポンスを作る**ため、元の例外が持っていたヘッダー（`Allow`）が捨てられる。
- テストが 405 の**ステータスとボディしか見ていなかった**ため検知できなかった。
- 対応: Sprint 1 開始前に修正し、PATCH リリース v0.1.1。

### Bước 2 — Sửa handler

`app/errors.py`, trong `handle_http_exception`:

```python
    # TODO(1): tạo response JSON như hiện tại (jsonify(...)), lưu vào biến
    # TODO(2): lấy danh sách header của exception: error.get_headers()
    #          → là list các cặp (tên, giá trị)
    # TODO(3): chép các header đó sang response, NGOẠI TRỪ "Content-Type"
    #          (vì response của mình là JSON, không phải HTML)
    # TODO(4): return response, status
```

Gợi ý cú pháp: vòng `for name, value in ...:`, so sánh không phân biệt hoa thường `name.lower() != "content-type"`, gán `response.headers[name] = value`.

Chạy `pytest` → test mới **xanh**, test cũ vẫn xanh. Rồi `curl -i -X POST .../health` phải thấy `Allow`.

📝 README: CÓ — mục **Định dạng lỗi API**: thêm 1 câu "405 có kèm header `Allow` liệt kê method được phép".
